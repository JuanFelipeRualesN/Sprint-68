El recorrido completo

Cada cuento pasó por los mismos seis pasos. Cada paso tiene su propio script, así que se puede repetir si algo cambia.

  1. 1

    Extraer y emparejar el texto

    Se leyeron los documentos Word y PDF de cada grado y se separó cada cuento por párrafos, con su versión en español y en inglés lado a lado.
  2. 2

    Traducir lo que faltaba

    Solo la carpeta de inglés traía Kinder. Para todo lo demás hubo que traducir. Es traducción automática y no ha sido revisada por una persona.
  3. 3

    Generar el JSON de cada cuento

    Se armó un archivo con el formato que pide el sistema: título, nivel, categoría y slides.
  4. 4

    Subir los cuentos por la API

    Un script envía cada JSON al sistema y guarda el resultado en un registro (subidos.csv).
  5. 5

    Crear una portada por cuento

    Se escribió una escena para cada cuento y se generó la imagen con IA (estilo Pixar).
  6. 6

    Enlazar las portadas

    Las imágenes se subieron al storage de Azure y se actualizó la base de datos para que cada cuento apunte a su imagen.

Paso 3: el JSON de cada cuento

El script generar_json_med.py lee los cuentos emparejados y crea un archivo por cuento. Las reglas que acordamos:

  • Si el cuento tiene hasta 110 palabras, va en un solo slide.
  • Si es más largo, se agrupan párrafos en slides de unas 90 palabras, sin pasar de 110 y sin cortar oraciones.
  • Primero a Quinto usan el nivel 1 al 5. Kinder usa el nivel 7, porque el sistema rechaza el nivel 0.
  • Las cuatro metas (fluidez, exactitud, completitud, pronunciación) valen 70.
herramientas/generar_json_med.py (reglas)
NIVEL = {"Primero": 1, "Segundo": 2, "Tercero": 3, "Cuarto": 4, "Quinto": 5}
NIVEL_KINDER = 7   # el endpoint rechaza LevelId 0 ("LevelId is required.")
CATEGORIA_ID = {"animals": 1, "scifi": 2, "history": 3, "adventure": 4}
MAX_PALABRAS = 110   # tope por slide
OBJETIVO = 90        # tamaño aproximado al dividir

Paso 4: subirlos al sistema

El script subir_cuentos.py usa solo la librería estándar de Python. Por defecto simula y no envía nada. Solo sube de verdad si se le pasa --enviar. Cada envío queda anotado con su código de respuesta y el Id que le dio el sistema.

Cómo se usa el subidor
python3 herramientas/subir_cuentos.py                     # simula, no envía nada
python3 herramientas/subir_cuentos.py --enviar --limite 1 # prueba con un solo cuento
python3 herramientas/subir_cuentos.py --enviar            # sube todos los de la carpeta
python3 herramientas/subir_cuentos.py --enviar --carpeta salida/json_med_kinder
Resultado: los 108 envíos respondieron 201 (creado). Primero a Quinto quedaron en los Ids 48 a 120 y Kinder en los Ids 121 a 155.

Paso 5: las portadas con IA

Para cada cuento se escribió una escena corta en inglés que resume de qué trata. El script la mete en el formato de prompt que pidió el equipo y la manda al modelo de imágenes de Google (Nano Banana 2 Lite, gemini-3.1-flash-lite-image).

herramientas/escenas_imagenes.json
"primero-es-01": "a smiling grandma serving a huge pot of rice with sausages to her family",
"segundo-es-06": "a tiny coquí frog singing on a leaf in a Puerto Rican rainforest at night",

# Un valor que empieza con "=" es un prompt completo, sin el título (para los que el filtro bloquea):
"tercero-es-13": "=Pixar style 3D animated illustration: a cute fluffy giant panda sitting in a green bamboo forest ... No text or letters in the image."
herramientas/generar_prompts_imagenes.py
prompt = f'Pixar style, generate an image for "{titulo_en}": {escena}. No text or letters in the image.'

Así quedan algunos prompts completos, tal como se enviaron:

Pixar style, generate an image for "The Moon": a child climbing a ladder of stars up to a big smiling moon to pick the prettiest star for grandma's room. No text or letters in the image.

Pixar style, generate an image for "The Coquí": a tiny coquí frog singing on a leaf in a Puerto Rican rainforest at night. No text or letters in the image.

Pixar style, generate an image for "Egypt": ancient Egypt with a pharaoh, a stone palace, pyramids and workers by the Nile. No text or letters in the image.
herramientas/generar_imagenes.py (la parte importante)
MODELO = "gemini-3.1-flash-lite-image"   # "Nano Banana 2 Lite" en AI Studio

cuerpo = {"contents": [{"parts": [{"text": prompt}]}],
          "generationConfig": {"responseModalities": ["TEXT", "IMAGE"],
                               "imageConfig": {"aspectRatio": "16:9"}}}
# La API key NO está en el código: se lee de GEMINI_API_KEY o se pide por teclado.
key = os.environ.get("GEMINI_API_KEY") or getpass.getpass("API key (no se muestra): ")
Cómo se usa el generador
python3 -I herramientas/generar_imagenes.py                        # simula
python3 -I herramientas/generar_imagenes.py --generar --limite 1   # prueba con una
python3 -I herramientas/generar_imagenes.py --generar --proporcion 16:9
# Si se corta por cuota, se vuelve a correr y sigue donde se quedó (salta las que ya existen).

El script no guarda la API key en ningún archivo. La lee del entorno o la pide por teclado sin mostrarla.

Paso 6: enlazar las portadas en la base de datos

Las imágenes se suben al storage de Azure con el nombre med_story_<Id>.jpg. La dirección final de cada una es:

https://stpubliceastus001.blob.core.windows.net/public-assets/stories/med_story_<Id>.jpg

El script preparar_portadas.py renombra las imágenes y escribe el SQL que actualiza la base de datos. Cada UPDATE exige que el Id y el título coincidan. Si un Id no corresponde a su cuento, no cambia nada.

salida/actualizar_portadas_med.sql (un cuento de ejemplo; el archivo trae 108)
USE gs_reading_ai_db_prod;
START TRANSACTION;

UPDATE stories SET image_url = 'https://stpubliceastus001.blob.core.windows.net/public-assets/stories/med_story_84.jpg'
 WHERE id = 84 AND title_en = 'The Price of the Shortcut';

UPDATE story_slides SET image_url = 'https://stpubliceastus001.blob.core.windows.net/public-assets/stories/med_story_84.jpg'
 WHERE story_id = 84;

-- verificar los conteos y, si cuadran:
COMMIT;      -- si no cuadran: ROLLBACK;

La verificación dio 108 cuentos actualizados y 212 slides actualizados. La corrección de una portada no necesita SQL: se reemplaza el archivo en el storage con el mismo nombre y la dirección sigue igual.
